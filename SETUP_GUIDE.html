Setup guide GitHub Desktop edition

The easy version. You use buttons in GitHub Desktop for Git and only type two Quarto commands in Terminal. One-time setup ~20 minutes; after that, publishing an update takes about a minute.

The 6 steps

  1. Install Quarto
  2. Sign in to GitHub Desktop & clone the repo
  3. Preview the site locally
  4. Publish the site (first time)
  5. Turn on GitHub Pages
  6. Day-to-day: edit & update

Plus an optional Step 7 — send an offline copy to a friend.

Step 1 — Install Quarto

Quarto is what turns your .qmd files into web pages.

  1. Go to quarto.org/docs/get-started.
  2. Download the Mac installer and run it. Accept the defaults.
  3. Open Terminal (Applications → Utilities → Terminal) and check it installed: 
    quarto --version
    You should see a version like 1.5.57. If you see “command not found”, restart your Mac and try again.

Step 2 — Sign in to GitHub Desktop and clone the repo

GitHub Desktop replaces everything you'd otherwise do with terminal Git.

  1. Open GitHub Desktop.
  2. Sign in with your GitHub account (File → Options → Accounts → Sign in on Windows, or GitHub Desktop → Settings → Accounts on Mac).
  3. Clone your website repo: File → Clone repository → pick Wantidah/wantidah.github.io from the list → choose a local folder (e.g. /Users/whorpien/wantidah-website) → click Clone.
  4. If the repo is empty on GitHub, copy all the files from your current project folder into the cloned folder (so they live alongside the hidden .git folder).
  5. GitHub Desktop will immediately show the files in its “Changes” tab. Write a short summary at the bottom-left (e.g. “Initial site scaffold”) and click Commit to main, then Push origin at the top.
Already using this folder as your project? Instead of cloning, in GitHub Desktop use File → Add local repository and point it at /Users/whorpien/wantidah-website. If it says “not a git repo”, click create a repository when prompted, then use Repository → Push to send it up.

Step 3 — Preview the site locally

Before publishing, check the site looks right on your Mac.

  1. In Terminal, change into the website folder: 
    cd /Users/whorpien/wantidah-website
  2. Start the preview: 
    quarto preview
    This opens your browser at something like http://localhost:4444. Any time you save a .qmd file, it reloads automatically.
  3. Click through: Home → About → Research → Publications → Blog → Contact (all inside the three-line menu at the top-left).
  4. Press Ctrl+C in Terminal to stop the preview when done.

Step 4 — Publish the site (first time)

Quarto has a one-liner that builds the site and pushes it to a special gh-pages branch.

  1. In Terminal (still in the project folder): 
    quarto publish gh-pages
  2. Type y when it asks you to confirm.
  3. Quarto will render the site and push it. When it finishes, it prints your live URL: https://wantidah.github.io.
If it fails with “repo not found” or a permissions error, run gh auth login once (install from cli.github.com), or make sure you're signed in to GitHub Desktop. Retry.

Step 5 — Turn on GitHub Pages

One-time switch in your repo's settings.

  1. Go to your Pages settings.
  2. Under Source, pick Deploy from a branch.
  3. Under Branch, pick gh-pages and folder / (root). Click Save.
  4. Wait ~1 minute, refresh, and you'll see: Your site is live at https://wantidah.github.io.

Step 6 — Day-to-day: edit & update

The short loop you'll use forever.

A. Edit

Open the .qmd file in your editor (RStudio, VS Code, anything). Save.

B. Preview (optional but nice)

quarto preview

C. Save changes to GitHub (with GitHub Desktop)

  1. Open GitHub Desktop. You'll see your edits in “Changes”.
  2. Write a short summary (e.g. “Add May blog post”).
  3. Click Commit to main.
  4. Click Push origin at the top.

D. Publish the updated site

quarto publish gh-pages

Type y to confirm. Changes appear at https://wantidah.github.io within a minute.

Cheat sheet — the whole workflow:
Edit your .qmd → Commit & Push in GitHub Desktop → run quarto publish gh-pages in Terminal. Done.

Add a new blog post

  1. In Finder, duplicate posts/welcome/ and rename to something like posts/2026-05-bats-and-ranches/.
  2. Open index.qmd inside it and update the front matter: 
    ---
title: "Bats and ranches: notes from the field"
description: "What we saw in northern Thailand this May"
date: "2026-05-02"
categories: [wildlife, field-notes, one-health]
image: thumbnail.jpg
---
  3. Write your post, drop a thumbnail.jpg in the same folder.
  4. Preview → Commit & Push (GitHub Desktop) → quarto publish gh-pages.

Step 7 — Send an offline copy to a friend (optional)

If someone wants to see the site without it being live (e.g. draft feedback), you can bundle the whole site into one zip.

  1. In Terminal: 
    cd /Users/whorpien/wantidah-website
chmod +x build-offline.sh   # first time only
./build-offline.sh
  2. You'll get wantidah-website-offline.zip in the project folder. Email it or drop it in Dropbox.
  3. Your friend unzips anywhere, double-clicks index.html, and the site opens in their browser. No internet, no server.

Quick troubleshooting

“quarto: command not found” — Quarto isn't on your PATH. Restart Terminal, or restart your Mac. Check with which quarto.

Pages shows a README, not the site — the Pages source is pointing at main. Go back to Step 5 and pick gh-pages.

I updated but the live site looks old — hard-refresh (Cmd+Shift+R). GitHub Pages caches for a few minutes.

Conflict in GitHub Desktop — click Pull first (top bar), resolve any highlighted files, then commit & push again.
